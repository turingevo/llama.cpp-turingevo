# 同步上游 (ggml-org/llama.cpp) 最新代码

本仓库有两个 remote:

| remote | 地址 | 用途 |
| --- | --- | --- |
| `upstream` | https://github.com/ggml-org/llama.cpp | 官方仓库，只读，用来拉最新代码 |
| `origin` | git@github.com:turingevo/llama.cpp-turingevo.git | 自己的 fork，只保留 `turingevo` 一个分支 |

`master` 是上游镜像，本地跟踪 `upstream/master`；`turingevo` 是开发分支，跟踪 `origin/turingevo`。
上游更新用 merge 而不是 rebase，避免 force push。

## 一步到位

```sh
git fetch upstream
git switch master
git merge --ff-only upstream/master
git switch turingevo
git merge master
git push
```

## 逐条说明

```sh
# 1. 拉上游最新提交（不动工作区）
git fetch upstream

# 2. master 只做上游镜像，必须能 fast-forward，否则说明本地 master 被改过
git switch master
git merge --ff-only upstream/master

# 3. 把上游代码合并进开发分支，冲突在这里解决
git switch turingevo
git merge master

# 4. 编译 + 测过之后再推
git push
```

## 冲突处理

冲突基本只会出现在模型代码和 `common/` 目录。处理原则:

- 上游对 SenseNova-U1 的改动优先接受，再检查 `src/models/sensenova-u1.cpp` 里的
  生成分支 (`llama_set_gen_pass`) 是否还在
- `tools/sensenova-u1/` 和 `tools/sensenova-server/` 是本地新增目录，上游不会碰，
  除非 `common/` 的接口变了
- 解完冲突后跑 `turingevo/shared/build-all-dev.sh` 和 `turingevo/sensenova/cli.sh` 验证

## 常见问题

**`git merge --ff-only upstream/master` 报 not possible to fast-forward?**

说明本地 `master` 上有上游没有的提交。先确认这些提交是否已经合进 `turingevo`，
确认后 `git reset --hard upstream/master`（会丢弃本地 master 的改动，确认前先看 `git log`）。

**要不要用 GitHub 网页上的 Sync fork 按钮?**

只能同步与上游同名的分支，本仓库远端已经没有 `master`，所以按钮用不上。
全部在本地合并，再 `git push` 推送 `turingevo` 分支。
